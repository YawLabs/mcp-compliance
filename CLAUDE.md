# mcp-compliance

MCP server compliance testing tool. Tests any Streamable HTTP or stdio MCP server against the MCP specification, one revision per run: **2025-11-25** (88 tests: 16 transport, 21 lifecycle, 4 tools, 5 resources, 3 prompts, 10 errors, 6 schema, 23 security) or **2026-07-28** (103 tests: 20 transport, 22 lifecycle, 6 tools, 8 resources, 4 prompts, 12 errors, 10 schema, 21 security). `--spec-version auto` (default) probes the server and grades the newest revision it speaks; `2025-11-25` / `2026-07-28` pin one.

## Architecture

- `src/index.ts` — CLI entry point (Commander.js). Subcommands: `test`, `benchmark`, `diff`, `init`, `mcp`. `--spec-version` on `test` and `benchmark`; `--list` previews offline (under `auto`, the default, both catalogs are printed in their own sections; `--spec-version <date>` previews one). `RunOptions.onStatus` feeds the dim pre-test stderr status lines in terminal mode only (the stdio era probe still waiting after ~2 s; an HTTP preflight timeout being re-probed).
- `src/spec.ts` — `SUPPORTED_SPEC_VERSIONS`, `SpecVersion` / `SpecVersionOption` (`auto`), `LEGACY_SPEC_VERSION` / `MODERN_SPEC_VERSION` / `DEFAULT_SPEC_VERSION` (the unreachable-server fallback, 2025-11-25), `specEraOf()`, `specBaseFor()`, `parseSpecVersionOption()`. Everything revision-dependent resolves through here; there is no global "current spec" constant any more.
- `src/detect.ts` — `detectSpecVersion()` / `classifyDiscoverResponse()`: the spec's dual-era client rule. One conformant modern `server/discover`; a `DiscoverResult` or a modern error code (-32020/-32021/-32022) means 2026-07-28, anything else (any other error, HTTP 4xx/HTML, no reply within the budget) means 2025-11-25; a 401/403 without a modern body is 2025-11-25 with `eraUndetermined: true` so a pinned run never says "re-run with 2025-11-25" for a missing `--auth`. Every `reason` starts with the exported `REASON_PREFIX` (`server/discover -> `), which the reporter folds into the header label. `buildDiscoverProbe()` is shared with the HTTP preflight so detection costs no extra round-trip.
- `src/runner.ts` — Public API + dispatcher + the legacy suite body. `runComplianceSuite()` resolves the spec version (preflight/probe: on HTTP a timed-out preflight is re-probed once within `startupTimeout` under `auto`; on stdio a child that exits on the probe is reported with its exit code and stderr tail and re-spawned; a pinned HTTP run warns when the preflight answered in the other era), warns on `--only`/`--skip` values unknown to the resolved catalog, then dispatches to `runModernSuite()` or runs the 2025-11-25 body inline. Re-exports everything library consumers need: `SUPPORTED_SPEC_VERSIONS`, `specBaseFor`, `getTestDefinitions`, `findTestDefinition`, `MODERN_TEST_DEFINITIONS`, `TEST_DEFINITIONS`, `detectSpecVersion`, `computeGrade/computeScore`, `previewTests` (takes `specVersion`), `parseSSEResponse`. `SPEC_VERSION` and `SPEC_BASE` are still exported with their 2025-11-25 values but are `@deprecated`.
- `src/harness.ts` — `createHarness()`: the per-test runner both suites share (`check(id, fn, {required})` — name/category/specRef come from the catalog; retries; `parallelSafe` pool + `drainPool()`; `--only`/`--skip`; warnings dedup + cap at `MAX_WARNINGS = 50` with the `"... and N more warning(s) suppressed"` sentinel; `TestResult.skipped` from an explicit `TestOutcome.skipped`, else from the details markers `readsAsSkip()` reads -- a leading `Skipped`, `(skipped)`, `not applicable` -- and never on a failure; the score leaves skips out, see `src/grader.ts`). `supportsTransportByDefinition()` is the catalog-only transport gate the modern suite uses.
- `src/types.ts` — TypeScript interfaces + `TEST_DEFINITIONS` (the 2025-11-25 catalog, 88 entries). `TestDefinition.specRef` is relative to the catalog's spec base.
- `src/definitions/2026-07-28.ts` — `MODERN_TEST_DEFINITIONS` (103 entries). `src/definitions/index.ts` — `getTestDefinitions(version)`, `getTestDefinitionMap()`, `findTestDefinition()`. Id policy: a shared id covers the same feature, but its wording, criteria and required flag may differ between the catalogs (stdio-framing, error-invalid-jsonrpc and error-method-code flip required); a check whose verdict on the same behaviour flipped gets a new id, so ids are comparable only within one catalog. `transports` on a definition is the only transport gate in the modern catalog.
- `src/suites/modern/` — the 2026-07-28 suite split per category: `index.ts` (`runModernSuite()`, assembles the report), `context.ts` (`ModernSuiteContext`, `hasTools/hasResources/hasPrompts/hasCompletions`, and the `ensureTools/ensureResources/ensurePrompts/ensureResourceTemplates` loaders that fetch a list once on demand so `--only <category>` measures instead of skip-passing), `transport.ts`, `stdio.ts`, `lifecycle.ts` (`runLifecycle` first; `runLifecycleLate` holds completions, progress-token, the two claim-less `_meta` probes and the fresh-process `lifecycle-dual-era`; exports `notEvaluable()` for the attributable rejection probes), `features.ts` (tools/resources/prompts), `errors.ts`, `schema.ts`, `security.ts` (single-target injection via `pickInjectionTarget`; `restartStdioServer` replaces a stdio child a check's own `tools/call` killed, on every attempt, and `security-tool-rug-pull` then reads both lists from the replacement), `posthoc.ts` (the eight Recorder scans that run after everything else has drained, and fail outright when the recording is empty).
- `src/modern/` — the modern wire envelope, built runner-side so tests can deliberately omit or corrupt it: `meta.ts` (`buildMeta()`, `withMeta()`, `META` key names, `MODERN_ERROR_CODES`, `RETIRED_ERROR_CODES`, `REMOVED_METHODS`, `MRTR_METHODS`, `CACHEABLE_METHODS`), `headers.ts` (`standardHeadersFor()`, `mcpNameFor()`, `mcpParamHeadersFor()`, Base64 sentinel `encodeHeaderValue()`/`decodeHeaderValue()`), `client.ts` (`createModernClient()` → `rpc/notify/stream/raw` with per-call meta/header overrides; `errorOf()`, `resultOf()`, `describeResponse()` helpers), `schema-validator.ts` (ajv 2020 dispatch over the vendored `src/schemas/mcp-2026-07-28.schema.json` by method / `resultType` / error code; `JSONValue` def patched).
- `src/recorder.ts` — `createRecorder()`: every server message the modern suite receives (JSON body, SSE frame, stdio line) paired with the request that produced it. Post-hoc tests and `schema-wire-valid` read it.
- `src/checks/patterns.ts` — spec-neutral tables shared by both suites: injection payloads, stack-trace / internal-IP / rejection / poisoning patterns, `VALID_CONTENT_TYPES`.
- `src/grader.ts` — Scoring algorithm: required tests 70%, optional 30%, over MEASURED tests only (a skip, `passed && skipped === true`, is left out of numerator and denominator; it still counts in `summary.passed`); an empty measured bucket renormalises to the other; zero tests, or every test skipped, scores 0 (F) -- `overall` is unchanged ("fail" only on required failures or an empty run), and the terminal / GitHub / markdown / HTML reports, the SARIF invocation properties (`note`) and the MCP test tool say "No test measured anything" via `nothingMeasuredNote()`. The terminal category bars and HTML category cards score what was measured too (`--` / neutral when a category measured nothing). Grade thresholds: A>=90, B>=75, C>=60, D>=40, F<40.
- `src/reporter.ts` — Terminal (chalk), JSON, SARIF, GitHub, Markdown, HTML formatters, plus `formatProgressLine()` (the `--verbose` line) and `statusLabel()` (PASS / FAIL / SKIP, shared with the MCP test tool). Recommendation lookup is by (specVersion, id). SARIF `automationDetails.id` is `mcp-compliance/<specVersion>/` so Code Scanning tracks the two suites separately; `helpUri` uses `specBaseFor(report.specVersion)`.
- `src/diff.ts` — refuses to diff reports with different `specVersion`s (ids are only comparable within one catalog) and names the `--spec-version` to pin. Classifies each test as pass / fail / skip: checks that start or stop skipping go to `newlySkipped` / `noLongerSkipped` and never fail the diff; a report without skip data (0.18.x) has its skips read from their wording (`readsAsSkip`). The grade line is NOT copied from the files: both reports are rescored with `computeScore()` from their results (skip per the same pass/fail/skip reading), so a 0.19.0 baseline that scored skips as passes compares like with like; `recordedScores` keeps a file's own score/grade when it differs (`skipsAsPasses` says whether 0.19.0-style scoring reproduces it) and `formatDiff` prints a note for each.
- `src/benchmark.ts` — spec-aware: measures `ping` after an `initialize` handshake on 2025-11-25, `server/discover` on 2026-07-28 (no `ping` there) after one unmeasured `server/discover` warm-up on pinned runs (under `auto` the detection probe is the warm-up); JSON-RPC error replies count as failures, not successes.
- `src/config.ts` — config file loader; `specVersion` key (`auto` | date); `format` accepts every CLI format.
- `src/mcp/server.ts` — MCP server entry point (SDK v1, so the dogfood target speaks 2025-11-25). Exports `createComplianceServer()` and `startServer()`.
- `src/mcp/tools.ts` — 2 MCP tools: `mcp_compliance_test` (HTTP URL targets; `specVersion` input) and `mcp_compliance_explain` (`specVersion` optional; searches both catalogs when omitted). All have annotations.
- `action.yml` — GitHub Action: `spec-version` input (default `auto`), `spec-version` output = the resolved revision; the JSON pass resolves it and the SARIF/visible passes are pinned to that value.

## Build

- **Bundler:** tsup with two entry configs (CLI with shebang, library with types).
- **Linter:** Biome (not ESLint). `npm run lint` wraps it in `scripts/lint.mjs`, which provisions a working binary on MINGW64-ARM64.
- **Tests:** Vitest (globals on, 30 s test timeout).
- **TypeScript:** Strict mode, ES2022 target, ESM.

## Key patterns

- **Two catalogs, one report schema.** Both suites use the same 8 categories, so `schemas/report.v1.json` is unchanged; `report.specVersion` is always the RESOLVED revision (never `auto`) and test ids are only meaningful together with it. Reports from different revisions are not diffable.
- **Legacy suite (2025-11-25):** transport tests run pre-initialization using raw HTTP (undici); lifecycle tests drive the `initialize` handshake, then post-init tests. Session state (`Mcp-Session-Id`, negotiated protocol version) is tracked and injected into subsequent requests. Request IDs use a counter starting at 1000 to avoid collision with hardcoded transport test IDs (99901-99904). HTTP-only ids are gated on stdio by `STDIO_INCOMPATIBLE_IDS` plus the "transport category is HTTP" rule in `supportsTransport()`.
- **Modern suite (2026-07-28):** stateless. Every request carries `params._meta` (protocol version, client capabilities, client info) and, on HTTP, the mirrored `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` headers; the suite never calls `transport.setSessionId`. `server/discover` (seeded from the detection probe) is the capability source. Capability-gated tests are wrapped in `if (hasTools(ctx))` etc. — absent from the report when the capability is missing — and pass `{ required: true }` at runtime. Post-hoc tests scan the Recorder after `drainPool()`. Module order: lifecycle (discover + early probes), features, transport, errors, schema, stdio, the late lifecycle block, security, post-hoc. The two claim-less `_meta` probes run in the late block because an SDK 2.0 stdio server (`legacy: 'serve'`) pins its era on the first claim-less message (`ensureEraPinned` sends a list or `ping` first under `--only`); the late block runs BEFORE security so a gateway tripped by the rate-limit burst cannot answer it 429. `lifecycle-dual-era` ends the late block and on stdio goes to a fresh child (`spawnFresh`), because a dual-era server selects its era per process and the suite's process is already modern; an unanswered exit spawns an idle instance to tell a single-instance server from one that exits on `initialize`. The six `_meta` / header rejection tests fail as "not evaluable" when the conformant discover was itself rejected (`notEvaluable()`) or the answer is a 401/403/413/415/429 (`transportLevelRejection()`); `listUnavailable()` fails a list-dependent check with the recorded reason when its `-list` test is not in the run.
- **Detection is one request.** On HTTP the preflight body IS the modern `server/discover` probe, bounded by `preflightTimeout`; a timed-out preflight is re-probed once within `startupTimeout` under `auto`. On stdio the probe is the first exchange, bounded by `startupTimeout`, with a status line via `onStatus` after 2 s. Unreachable servers fall back to 2025-11-25 so every test that needs the server fails (the modern post-hoc scans fail on an empty recording too). Dual-era servers are graded as 2026-07-28 with a warning naming the other era, keyed on `supportedVersions` OR `state.legacyInitializeServed` (SDK 2.0 advertises only modern versions yet serves `initialize`).
- Security tests run after all functional tests. In the modern suite `security-auth-required` / `-www-authenticate` / `-oauth-metadata` probe with or without `--auth` (only `-auth-malformed` and `-token-in-uri` need a credential); the legacy suite still requires `--auth` for most of its auth tests (its `security-auth-required` runs without it on the unauthenticated preflight: a 401, or a 403 carrying a `WWW-Authenticate: Bearer` challenge, passes; a bare 403 fails as not evaluable, since Host/Origin validation and gateways answer one; an `initialize` served with no credential fails as not requiring auth). A bare 403 the credentialed twin ping could not get past makes the legacy siblings skip with the modern suite's wording (`Skipped: HTTP 403 without a Bearer challenge, not attributable to authentication (see security-auth-required)`). The injection target comes from the safest annotation tier (`toolSafety()`: readOnlyHint true, destructiveHint false, unannotated, destructiveHint true). Input-validation tests are gated on the `tools` capability. All security tests are optional by default (severity: warning).
- Stdio transport tests (3 legacy / 4 modern, `transports: ["stdio"]`) only run when testing a stdio server; HTTP-only tests skip on stdio.
- SSE parsing handles multi-line `data:` fields per the SSE spec. Exported and unit-tested. The `Transport` interface (`src/transport/index.ts`) has `stream()` (a request whose response stream is held open and read incrementally, with `close()`), `onMessage()` (every server message including id-less notifications, feeding the Recorder), and `signal` in the request init; request ids may be strings or numbers.
- Preflight connectivity check warns early if server is unreachable.
- Warnings array is deduplicated (exact-match) and capped at 50 entries after all tests drain. A sentinel `"... and N more warning(s) suppressed"` is appended when truncation occurs.
- **Spec version single source:** `src/spec.ts`. Never add a new `"2025-11-25"` / `"2026-07-28"` literal outside it, the catalogs, and tests.
- **Doc parity is enforced.** `src/tests/types.test.ts` checks per-catalog counts and the README's "What the N tests check (<version>)" sections; `src/tests/catalog-parity.test.ts` checks `mcp-compliance-rules.json` (per `specVersion`) and the `#### \`<id>\`` headings in `COMPLIANCE_RUBRIC.md` sections 3 / 3b against both catalogs. Adding or changing a test means updating all three docs in the same change; for 2026-07-28, `npx tsx scripts/gen-catalog-docs.ts` regenerates the rules entries and rubric section 3b (edit its criteria table for the new id). The methodology version (`specVersion`/`specDate` in that script, and the rubric header) must move together -- `catalog-parity.test.ts` checks it -- and a scoring change is a major bump (rubric section 6).
- **Fixtures:** `src/tests/fixtures/echo-server.mjs` (legacy stdio, answers `server/discover` with -32601), `legacy-silent-server.mjs` (ignores unknown pre-init methods, proves detection falls back on timeout), `modern-server.mjs` (2026-07-28 over stdio and HTTP; `MODERN_FIXTURE_BREAK=<knob>` env makes specific MUSTs fail so each modern check is seen going red). `src/tests/helpers/modern-fixture.ts` spawns them.

## Release process

Run `./release.sh <version>`. The script is idempotent — safe to re-run on failure. This repo has **no GitHub Actions CI** (workflows were removed; Actions is disabled on the repository), so `release.sh`'s local build + lint + typecheck + full test gate is the only gate: do not skip its lint step, and do not assume anything downstream re-checks formatting.

```bash
npm run build      # Compile with tsup

npm run lint       # Biome check (via scripts/lint.mjs)
```
